[[ransomware-resilience]]
=== Resilienza al ransomware



==== Configurazione avanzata dell'ambiente di ripristino isolato

Ransomware Resilience offre ora un flusso di lavoro migliorato per la configurazione di ambienti di ripristino isolati. Il nuovo flusso di lavoro chiarisce e semplifica il processo di configurazione di un ambiente di ripristino isolato per il cloud o ambienti on-premises.

Per ulteriori informazioni, vedi link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore.html["Crea un ambiente di ripristino isolato per un ripristino pulito"^].



==== Flusso di lavoro ottimizzato per abilitare il monitoraggio delle attività degli utenti

Ransomware Resilience ha migliorato il flusso di lavoro per abilitare il monitoraggio dell'attività degli utenti. In precedenza, Ransomware Resilience verificava la connessione del data collector ogni volta che abilitavi una strategia di protezione dal ransomware con il monitoraggio dell'attività degli utenti su un workload. Con questo aggiornamento, questo controllo viene ora saltato se esiste un data collector per la storage VM ed è nello stato "running", accelerando il flusso di lavoro di protezione.

Per ulteriori informazioni, consulta link:link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["proteggere i carichi di lavoro"^].



==== Il livello di servizio Flex di Google Cloud NetApp Volumes è generalmente disponibile

Il supporto per il livello di servizio Flex di Google Cloud NetApp Volumes in Ransomware Resilience è ora generalmente disponibile (GA).

=== Cloud Volumes ONTAP



==== Cloud Volumes ONTAP 9.19.1 in Azure

Ora puoi usare NetApp Console per distribuire e gestire la versione General Availability (GA) di Cloud Volumes ONTAP 9.19.1 in Azure.

La Console supporta Cloud Volumes ONTAP 9.19.1 in AWS e Google Cloud da agosto 2026.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Note sulla versione di Cloud Volumes ONTAP 9.19.1"^]



==== Crittografia di Azure nell'host per Cloud Volumes ONTAP

A partire da Cloud Volumes ONTAP 9.19.1 GA, la crittografia di Azure nell'host è abilitata per impostazione predefinita per le nuove implementazioni Azure a nodo singolo e ad alta disponibilità (HA) che soddisfano i prerequisiti. Questa funzionalità crittografa i dati sul server fisico che ospita la VM, inclusi il disco temporaneo e le cache associate a livello host, mentre i dati vengono scritti nell'host e letti dall'host.

Prima di distribuire Cloud Volumes ONTAP in Azure, assicurati che il tuo ambiente soddisfi i seguenti prerequisiti:

* La `EncryptionAtHost` funzionalità è registrata per il tuo abbonamento Azure. Consulta  https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Documentazione Microsoft: Abilitare la crittografia sull'host"^].
* Il tipo di istanze di macchine virtuali che hai selezionato supporta la crittografia nell'host nella tua area di Azure. Consulta  https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Documentazione Microsoft: trovare le dimensioni delle macchine virtuali supportate"^].


Nota questi punti:

* Non è necessaria alcuna configurazione aggiuntiva.
* Se questi prerequisiti non sono soddisfatti, la crittografia Azure nell'host non è abilitata per la tua implementazione di Cloud Volumes ONTAP.
* La crittografia a livello di host si applica solo ad Azure, non ad AWS o Google Cloud.


Documentazione Microsoft: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Usa il portale di Azure per abilitare la crittografia end-to-end usando la crittografia a livello host"^]



==== Crittografia di rete backend sui cluster Cloud Volumes ONTAP in Azure e Google Cloud

Cloud Volumes ONTAP 9.19.1 e versioni successive supportano la crittografia di rete del cluster backend per le configurazioni HA in Azure e Google Cloud.

L'attivazione della crittografia di rete del cluster potrebbe influire sulle prestazioni del cluster. Procedi con cautela e verifica che il tuo ambiente sia in grado di gestire il sovraccarico aggiuntivo prima di abilitare questa funzionalità.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Abilita la crittografia della rete backend sui cluster Cloud Volumes ONTAP"^]



==== Possibilità di ridurre le interruzioni durante la manutenzione pianificata di Azure

Durante la manutenzione pianificata, Azure può sospendere brevemente un'istanza di macchina virtuale in una coppia HA di Cloud Volumes ONTAP. ONTAP potrebbe interpretare la sospensione come un'interruzione del nodo e spostare le operazioni di storage sul nodo partner, per poi riportarle indietro quando l'istanza di macchina virtuale riprende a funzionare (takeover e giveback). Questo processo può interrompere le connessioni client attive anche in assenza di guasti dei nodi.

Con Cloud Volumes ONTAP 9.19.1 e versioni successive, puoi abilitare un'impostazione facoltativa che consente alla coppia HA di continuare a funzionare durante un blocco della manutenzione pianificata di Azure senza avviare automaticamente il takeover e il giveback.


NOTE: Questa funzionalità è disponibile in anteprima pubblica con Cloud Volumes ONTAP 9.19.1.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Previeni le interruzioni durante la manutenzione di Azure per le coppie HA di Cloud Volumes ONTAP"^]

==== Miglioramenti ai carichi di lavoro Hyper-V

In questa versione, Hyper-V workloads introduce i seguenti miglioramenti:

==== Miglioramento dei carichi di lavoro di Oracle Database

In questa versione, Oracle Database workloads introduce il seguente miglioramento:

*Gestione automatica dei file di log di archivio*: Durante le operazioni di ripristino e clonazione del database, NetApp Backup and Recovery rileva e monta automaticamente i file di log di archivio necessari, quindi li smonta al termine dell'operazione. Sono supportate le origini dei file di log primarie, secondarie e di storage a oggetti.

Per informazioni dettagliate sulla protezione dei carichi di lavoro Oracle Database, fare riferimento a https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Scopri come proteggere i carichi di lavoro di Oracle Database con NetApp Backup and Recovery"].

In questa versione, i carichi di lavoro di Microsoft SQL Server introducono il seguente miglioramento:

*Modifica delle licenze*: I costi non si applicano più ai backup che utilizzano architetture disk-to-disk o disk-to-disk fan-out. I costi si applicano solo ai backup nello storage a oggetti, inclusi i backup che utilizzano architetture 3-2-1 o disk-to-object-storage.

Per i dettagli sulla protezione dei carichi di lavoro di Microsoft SQL Server, consulta https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["Scopri come proteggere i carichi di lavoro di Microsoft SQL Server con NetApp Backup and Recovery"].



[[disaster-recovery]]
=== Ripristino dopo un disastro



==== Ordine di avvio facoltativo per i gruppi di risorse Kubernetes

NetApp Disaster Recovery ora supporta l'impostazione di un ordine di avvio facoltativo per i gruppi di risorse in un piano di replica Kubernetes, specificando un ordine di priorità e un tempo di ritardo facoltativo per le risorse. Questa opzione ti consente di avviare le risorse contemporaneamente quando necessario e di ritardare l'avvio delle risorse che dipendono da altre, aiutando le tue applicazioni a tornare online in modo corretto.

Per ulteriori informazioni, vedi link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/drplan-create.html["creare un piano di replica"^].



==== SnapLock supporto del volume

Disaster Recovery ora supporta i volumi SnapLock, consentendoti di eseguire il failover di snapshot a prova di manomissione.. Quando esegui il failback con i volumi SnapLock, devi usare l'opzione *Take snapshot now* per assicurarti che il failback venga completato correttamente.

Per ulteriori informazioni, consulta le istruzioni per link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["failover"^] e link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["failback"^].



==== Procedure semplificate di aggiornamento e conformità

Le esecuzioni di aggiornamento per vCenter, i piani di replica e la conformità sono state semplificate in un unico processo per consentire un'esecuzione più rapida. Per visualizzare questa modifica, scopri come fare link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["monitora i job"^].



==== Controlli di conformità di Kubernetes

Disaster Recovery ha aggiunto controlli di conformità per identificare gli ambienti di lavoro mancanti per i carichi di lavoro Kubernetes. Questi controlli di conformità contribuiscono a garantire lo stato di salute dei carichi di lavoro per l'integrità dei tuoi piani di replica.

=== Cloud Volumes ONTAP



==== Supporto per licenze basate sulla capacità nelle implementazioni in modalità privata

Ora puoi implementare i sistemi Cloud Volumes ONTAP in modalità privata con licenze basate sulla capacità in AWS, Azure e Google Cloud.

NetApp supporta solo il pacchetto Essentials per il modello di licensing basato sulla capacità in modalità privata. Acquista un pacchetto Essentials Bring-Your-Own License (BYOL) basato sulla capacità da NetApp e assegnalo al tuo sistema durante la distribuzione. I primi 500 GiB di capacità utilizzata non vengono conteggiati ai fini del pagamento della licenza. Puoi acquistare pacchetti aggiuntivi man mano che le tue esigenze di carico di lavoro crescono.

NetApp consiglia il modello di licensing basato sulla capacità per tutte le implementazioni Cloud Volumes ONTAP in modalità privata. Se hai implementazioni esistenti in modalità privata con licenze basate sui nodi, puoi convertirle al modello di licensing basato sulla capacità acquistando un pacchetto Essentials da NetApp. Questa nuova funzionalità di implementazione, insieme all'opzione di conversione, supporta il piano di NetApp di passare gradualmente dalle licenze basate sui nodi a quelle basate sulla capacità.

==== Correggi, ignora e riattiva le configurazioni per Cloud Volumes ONTAP in Microsoft Azure

La dashboard ben progettata di NetApp Console ora ti permette di correggere i suggerimenti di configurazione per i tuoi sistemi Cloud Volumes ONTAP.

Puoi anche escludere una o più configurazioni dall'analisi dell'architettura ben strutturata. Questo ti permette di ignorare configurazioni specifiche che non si applicano al tuo ambiente.

Se in seguito vuoi includere una configurazione precedentemente scartata, puoi riattivarla nella dashboard well-architected. Questo ripristina la configurazione nell'analisi e ti permette di ottenere suggerimenti e correzioni per essa.
